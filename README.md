# ინტერაქციის ანალიზი და მიკრო-ინტერაქციები (MediCare Hub)

## არჩეული მოდული: ექიმის ვიზიტის დაჯავშნა და ძიება

### 1. მიკრო-ინტერაქცია: ექიმის ბარათზე Hover ეფექტი

- **Trigger (ტრიგერი):** მომხმარებლის მაუსის კურსორის მიტანა (Hover) ექიმის ბარათზე.
- **Rules (წესები):** ჩაირთოს GPU-აქსელერირებული CSS გადასვლა (`transform: translateY(-4px)` და ჩრდილის გადიდება), რათა არ მოხდეს Layout Thrashing / CPU გადატვირთვა.
- **Feedback (უკუკავშირი):** ბარათი გლუვად იწევს ზემოთ 4 პიქსელით და იკვეთება ჩრდილი.
- **Loops / Modes:** დროებითი რეჟიმი (მაუსის მოცილებისას ბრუნდება საწყის მდგომარეობაში).

### 2. მიკრო-ინტერაქცია: ხელმისაწვდომობის მფეთქავი ინდიკატორი (Pulse Indicator)

- **Trigger (ტრიგერი):** კომპონენტის ჩატვირთვა ეკრანზე.
- **Rules (წესები):** `@keyframes pulseIndicator` მუშაობს მხოლოდ `transform: scale()` და `opacity` თვისებებზე 1.8 წამიანი პერიოდით.
- **Feedback (უკუკავშირი):** მწვანე წერტილის უწყვეტი, რბილი ფეთქვა, რაც მიუთითებს ექიმის აქტიურ სტატუსზე.
- **Loops / Modes:** უწყვეტი ციკლი (Infinite Loop).

### 3. მიკრო-ინტერაქცია: ექიმთან ვიზიტის დაჯავშნის ღილაკი

- **Trigger (ტრიგერი):** მომხმარებლის კლიკი „ვიზიტის დაჯავშნა“ ღილაკზე.
- **Rules (წესები):** მოვლენა იჭერება მშობელ კონტეინერზე Event Delegation-ით (`data-action="book"`), სისტემა აფიქსირებს არჩეული ექიმის ID-სა და სახელს და ეკრანზე აგენერირებს სტატუსის ბლოკს.
- **Feedback (უკუკავშირი):** გვერდის თავში მწვანე შეტყობინების გამოჩენა ჯავშნის დადასტურების შესახებ.
- **Loops / Modes:** მდგომარეობის შეცვლა (დახურვამდე აქტიური რჩება).

## დებაგინგის ჟურნალი (Debugging Journal)

### ბაგი 1: პარალელური მოთხოვნები და ორმაგი ჯავშანი (Race Condition & Double-Click)

1. **სიმპტომი:** მომხმარებლის მიერ „დაჯავშნის“ ღილაკზე სწრაფი ორმაგი დაკლიკებისას სისტემა აგზავნიდა ორ იდენტურ მოთხოვნას ერთსა და იმავე დროის სლოტზე (Overbooking რისკი).
2. **ჰიპოთეზა:** ღილაკს არ გააჩნდა `disabled` და `loading` მდგომარეობა პირველი მოთხოვნის დამუშავების პერიოდში, რის გამოც მოვლენის დამმუშავებელი მრავალჯერ იძახებოდა.
3. **DevTools დიაგნოსტიკა:** Network ტაბში დაფიქსირდა ორი პარალელური POST/Action ჩანაწერი რამდენიმე მილიწამის ინტერვალით. Console ტაბში ორივე ლოგი ერთდროულად დაიბეჭდა.
4. **Root Cause:** კომპონენტის მდგომარეობა (`state`) არ აკონტროლებდა მიმდინარე ოპერაციის სტატუსს კლიკის მომენტში.
5. **კოდის ფიქსი:** დაინერგა `bookingInProgressId` state. კლიკის მომენტში ღილაკი გადადის `disabled` რეჟიმში ტექსტით „მუშავდება...“, რაც ბლოკავს მეორე კლიკს ასინქრონული პროცესის დასრულებამდე.
6. **პრევენცია:** ფორმებსა და ტრანზაქციულ ღილაკებზე სავალდებულო გახდა თავდაცვითი შემოწმება (`if (isProcessing) return;`) და UI დონეზე ღილაკის გათიშვა.

### ბაგი 2: გაუთვალისწინებელი Runtime შეცდომისას ეკრანის გათეთრება (White Screen of Death)

1. **სიმპტომი:** რომელიმე ექიმის ობიექტში არასრული მონაცემის (მაგ. `undefined` ველის) რენდერის მცდელობისას მთელი React აპლიკაცია ქრაშავდა და რჩებოდა ცარიელი თეთრი ეკრანი.
2. **ჰიპოთეზა:** აპლიკაციაში არ არსებობდა Error Boundary, რომელიც დაიჭერდა შეცდომას კომპონენტების ხეში.
3. **DevTools დიაგნოსტიკა:** Console ტაბში გამოჩნდა Uncaught Error, ხოლო React Developer Tools-ში კომპონენტის ხე მთლიანად გაუჩინარდა.
4. **Root Cause:** React 16+-ში გაუმკლავებელი შეცდომები შლის მთელ DOM ხეს, თუ არ გამოიყენება `componentDidCatch`.
5. **კოდის ფიქსი:** შეიქმნა `ErrorBoundary.jsx` კლას-კომპონენტი `getDerivedStateFromError` და `componentDidCatch` მეთოდებით, რომელიც აჩვენებს რესპონსიულ Fallback UI-ს და „ხელახლა ცდის“ (Retry) ღილაკს.
6. **პრევენცია:** ყველა ძირითადი გვერდი და მოდული შეფუთულია ErrorBoundary-ით, რაც გამორიცხავს მთლიანი სისტემის დაქრაშვას ლოკალური ხარვეზის გამო.
